Chapter 25Administrator guide: setup and upkeep

For whoever looks after the technical side (often the owner with a little help). It explains how the application is hosted, which settings it needs, and how to switch on email, Google sign-in, online payments, the daily job and the AI Assistant.

25.1 What the system runs on

PartWhat it is
ApplicationA Next.js web application written in TypeScript, kept on GitHub (Sajeed25/nexpreneur-os).
HostingHostinger Deploy Web App (Node.js 20, Next.js preset, branch main). Every push to GitHub redeploys automatically.
DatabaseHostinger MySQL/MariaDB, managed with phpMyAdmin.
EmailA Hostinger mailbox over SMTP.
PaymentsRazorpay. Sign-in with Google (optional). OpenAI for the assistant (optional).
Note

Hostinger’s servers use an older system library, so the application is deliberately built on Next.js 15. Do not upgrade to Next.js 16 on this host: the build will fail.

25.2 Deploying from GitHub

  1. hPanel › Websites › Add website › Deploy Web App › Connect with GitHub and choose the repository.
  2. Set: Framework Next.js, Branch main, Node 20.x, build npm run build, start npm start.
  3. Open Environment variables and add the values in 25.4, then Deploy.
  4. When the deployment says Completed, open /api/health. You should see {"ok":true,"service":"nexpreneur-os"}.

25.3 The database

Create it

hPanel › Databases › Management: create a database, a user and a password. Hostinger adds a prefix, so the real names look like u123456789_nexpreneurOS. Use letters and numbers only in the password. Note the database name, user and host (usually 127.0.0.1).

Connection string

mysql://USERNAME:PASSWORD@127.0.0.1:3306/DATABASENAME

Type it yourself into the DATABASE_URL variable. Never paste it into chat, email or the repository.

Import the tables

In phpMyAdmin, click your database in the left list first (the heading must read “Database: …”), open Import, and run these files from the repository’s db folder, in this order:

#FileAdds
1mysql-schema.sqlOrganisations, locations, users, plans, resources, audit log
2mysql-0002-bookings.sqlBookings
3mysql-0003-billing.sqlMemberships, invoices, invoice lines, payments
4mysql-0006-password-reset.sqlPassword reset links, password-change tracking
5mysql-catchup.sqlEverything else: support, visitors, CRM, events, community, notifications, coupons, refunds, companies, services, images, sign-in links, and new columns
The most important rule

Update the database before deploying code that needs it. Each release may add columns. If the new code runs against an old database, sign-in fails with ER_BAD_FIELD_ERROR. The catch-up file is written to be safe to run again on an existing database, so when in doubt, run it first.

Afterwards the left list should show about 30 tables, including users, locations, resources, bookings, invoices, payments, events, leads and notifications.

25.4 Settings the application reads

Set these under Environment variables in hPanel, then Redeploy (changes take effect only after a redeploy).

Making a random secret

Open PowerShell (or any terminal with Node installed) and run:

node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"

Use a different value for AUTH_SECRET and for CRON_SECRET. Keep them private.

25.5 Email (SMTP)

  1. hPanel › Emails: create a mailbox such as noreply@yourdomain.com.
  2. Set SMTP_HOST=smtp.hostinger.com, SMTP_PORT=465, SMTP_USER = the full mailbox address, SMTP_PASS = its password, and SMTP_FROM=Nexpreneur OS <noreply@yourdomain.com>.
  3. Set AUTH_URL and redeploy.
  4. Test: use Forgot password? with your own email. The email should arrive within a minute (check spam the first time).

Email powers: password reset, email sign-in links, welcome invitations, emailed invoices, renewal and reminder emails, and visitor invitations.

25.6 Google sign-in

  1. Open Google Cloud Console › APIs & Services › Credentials › Create credentials › OAuth client ID › Web application. (If asked, first set up the OAuth consent screen with your app name.)
  2. Under Authorised redirect URIs add exactly: https://os.nexpreneur.com/api/auth/google/callback
  3. Copy the Client ID and Client secret into GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET. Redeploy.

The Google button on the sign-in page becomes active. People whose Google email matches an existing account sign in to it; others get a new member account.

25.7 Online payments (Razorpay)

  1. In the Razorpay dashboard create API keys. Start with Test mode keys. Put RAZORPAY_KEY_ID and RAZORPAY_KEY_SECRET in the settings.
  2. Razorpay › Webhooks › add https://os.nexpreneur.com/api/razorpay/webhook, tick the event payment.captured, and choose a webhook secret. Put the same secret in RAZORPAY_WEBHOOK_SECRET. Redeploy.
  3. Pay a test invoice with Razorpay’s test card. Confirm the invoice turns Paid.
  4. When happy, swap in Live keys and the live webhook.

25.8 The daily job (renewals and reminders)

Hostinger’s Node.js apps do not offer a Cron Jobs page, so use a free outside scheduler that calls your address once a day.

  1. Create a CRON_SECRET (25.4) and add it to the settings. Redeploy.
  2. Create a free account at cron-job.org and press Create cronjob.
  3. URL: https://os.nexpreneur.com/api/cron/daily   Schedule: every day at 07:00, time zone Asia/Kolkata   Method: GET.
  4. In Advanced add a header: name Authorization, value Bearer followed by your secret (the word Bearer, a space, then the secret).
  5. Press Test run. You should get {"ok":true,…}.
Test resultMeaning
200  {"ok":true,…}Working.
401 UnauthorizedThe header does not match CRON_SECRET (check the space after “Bearer”).
503 Not configuredCRON_SECRET missing, shorter than 16 characters, or the database is not connected. Redeploy after changing settings.
500 {"ok":false,"error":"ER_…"}A database problem. ER_BAD_FIELD_ERROR or ER_NO_SUCH_TABLE means run the catch-up SQL.

25.9 The AI Assistant (OpenAI)

  1. At platform.openai.com create an account, add a payment method and some credit, and create an API key.
  2. Put it in OPENAI_API_KEY (never share it). Optionally set OPENAI_MODEL. Redeploy.
  3. Under Billing › Limits set a monthly cap so costs can never surprise you.

25.10 Invoice details

Set SELLER_NAME (for example “Nexpreneur Technologies Pvt Ltd”) and SELLER_GSTIN (your 15-character GSTIN). They appear at the top right of every invoice and in invoice emails.

25.11 Updating the application

  1. If the release notes mention new database changes, run the SQL first (25.3).
  2. Push the new code to GitHub. Hostinger redeploys within a few minutes.
  3. Check /api/health, sign in, and open one page that changed.

25.12 Backups and checks

  • Hostinger makes daily backups. Also export your database from phpMyAdmin (Export › Quick › SQL) before every upgrade and keep the file somewhere safe.
  • /api/health is a public “is it running” check. When an owner is signed in, /api/health?deep=1 additionally reports which libraries load and whether the key settings are present (never their values).
  • Errors are written to hPanel › your site › Runtime logs.

Chapter 27Security and privacy

What protects your data, in plain language, and how to keep it that way.

27.1 What the system does for you

AreaProtection
PasswordsStored scrambled with bcrypt; nobody, including administrators, can read them. 8 to 72 characters. Sign-in is rate-limited.
SessionsA signed cookie that scripts cannot read, valid 8 hours. Your role is re-read from the database on every page, so role changes and deactivations apply at once. Changing a password signs out other devices.
PermissionsEnforced on the server for every action, not just by hiding menu items.
Your data onlyEvery query is limited to your organisation.
MoneyAmounts always come from the database; online payments are verified by signature and by asking Razorpay; payments are recorded exactly once; refunds are checked against what was paid.
Double-booking and overbookingBookings and event seats are locked while checked.
Email linksOne-time, stored only as a fingerprint, expire (15 min, 1 hour or 7 days) and are built from your configured address only.
AI AssistantCan only propose; you confirm; confirmations are signed, expire in 10 minutes and are tied to you.
UploadsOnly JPEG, PNG and WebP up to 900 KB, checked by content, never SVG.
Web protectionsHTTPS enforced, framing blocked, content security policy, and no sniffing of file types.
Audit trailImportant actions are recorded with who and when.

27.2 What you should do

  • Give each person their own account and the lowest role that lets them do their job.
  • Deactivate people the day they leave.
  • Never share passwords or the secrets in chapter 25. Do not paste them into chat or email.
  • Register the owner account immediately after launch and use a strong, unique password.
  • Keep database exports somewhere safe and test that you can restore one.
  • Sign out on shared computers.

27.3 What is stored about people

Name, email, phone, job title, company and emergency contact (entered by them or by staff); plan, bookings, invoices and payments; visitor names and optional contact details; community posts. The member directory shows only name, role and company. Card details are handled by Razorpay and never stored by Nexpreneur OS.

Known limits
  • Sign-up is open: anyone with the web address can create a member account. Staff roles are only granted by an owner.
  • The sign-in rate limit is kept in the server’s memory, so it resets when the server restarts.
  • Door access control, document storage and two-factor sign-in are not built yet.
